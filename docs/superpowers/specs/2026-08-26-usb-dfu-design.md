# USB DFU 与 A/B 固件回退设计

日期：2026-08-26
状态：已确认设计，待实施计划

## 1. 目标

本设计为 GD32F303CCT6 主控增加 USB Device Firmware Upgrade（DFU）能力。设备必须支持以下入口：

- 正常应用通过 MSC 配置盘中的一次性字段 `ENTER_DFU=1` 请求进入 DFU。
- 应用损坏时，用户可以在上电阶段按住板载按键进入恢复 DFU。

升级过程必须满足以下要求：

- Bootloader 只写非活动应用槽。
- 设备必须检查芯片型号、目标槽、加载地址、固件长度、版本和 CRC32。
- 下载期间断电或 USB 断开不得破坏当前已确认固件。
- 新固件未确认启动时，Bootloader 必须保留旧固件并支持自动回退。
- 下载成功后，设备必须自动复位并试运行新固件。
- `STAT_LED` 必须显示 DFU、校验、成功、失败、试运行和回退状态。
- 升级和回退不得清除现有设备配置。

数字签名和加密不在本设计范围内。CRC32 只提供传输完整性和误刷防护，不提供固件来源认证。

## 2. 当前约束

- MCU：GD32F303CCT6。
- 内部 Flash：256 KiB；擦除页大小为 2 KiB。
- SRAM：48 KiB。
- 当前 Release 固件约为 47.5 KiB。
- 当前应用从 `0x08000000` 启动。
- `0x0803F000–0x0803FFFF` 已用于设备配置双页存储。
- 当前应用 USB 设备由 MSC、CDC-ACM 和 CMSIS-DAP v2 接口组成。
- GD32 USB 库包含 DFU 示例，但产品实现不得直接采用示例的开放地址写入策略。设备端必须实施本文定义的边界、状态和错误检查。

## 3. 系统架构

系统由 Bootloader、两个应用槽、Boot 状态存储、设备配置存储、升级包和主机升级工具组成。

Bootloader 固定在 Flash 起始地址。每次上电或复位都先执行 Bootloader。Bootloader 根据一次性 DFU 标记、按键状态、Boot 状态和镜像有效性决定进入 DFU 或启动应用。

应用使用同一份源码生成两个链接地址不同的镜像。普通 Cortex-M4 应用不是位置无关代码，因此同一份 BIN 不得同时写入两个槽并直接执行。

主机升级工具使用标准 USB DFU 1.1 请求传输镜像。项目专用 `.dwup` 包负责携带两个链接地址版本及元数据。Bootloader 是最终安全裁决方，不得信任主机工具提供的槽、地址、长度、版本或 CRC 结论。

## 4. Flash 分区

| 区域 | 起始地址 | 结束地址 | 大小 | 用途 |
|---|---:|---:|---:|---|
| Bootloader | `0x08000000` | `0x08003FFF` | 16 KiB | DFU、镜像验证、选槽、回退和应用跳转 |
| Slot A | `0x08004000` | `0x08020FFF` | 116 KiB | A 地址应用镜像 |
| Slot B | `0x08021000` | `0x0803DFFF` | 116 KiB | B 地址应用镜像 |
| Boot 状态 | `0x0803E000` | `0x0803EFFF` | 4 KiB | 双页原子状态和试运行标记 |
| 设备配置 | `0x0803F000` | `0x0803FFFF` | 4 KiB | 保留现有配置双页存储 |

所有分区边界与 2 KiB Flash 页对齐。

Bootloader 的 DFU 写入层必须拒绝以下操作：

- 写入或擦除 Bootloader 区域。
- 写入或擦除当前活动槽。
- 通过镜像数据请求写入 Boot 状态区域。
- 写入或擦除设备配置区域。
- 写入目标槽之外的地址。
- 处理发生整数加法回绕的地址加长度组合。

链接脚本和构建脚本必须分别检查 16 KiB 和 116 KiB 的区域上限。构建不得通过截断镜像规避上限检查。

## 5. 进入 DFU

### 5.1 MSC 配置盘入口

应用的 `CONFIG.TXT` 支持一次性字段：

```text
ENTER_DFU=1
```

解析规则如下：

- 应用只接受精确字段名 `ENTER_DFU`。
- 值 `1` 表示请求进入 DFU。
- 值 `0` 表示不执行动作。
- 其他值或重复字段使本次配置无效。
- `ENTER_DFU` 不得写入设备配置 Flash 记录。
- 如果同一次文件写入还修改普通配置，应用必须先验证整份文件。只有所有字段有效时，应用才可以保存普通配置并执行 DFU 请求。
- 应用必须等待 MSC 文件写入事务完成后再执行复位。应用不得在收到第一个扇区写请求时复位。

应用接受请求后执行以下步骤：

1. 将配置盘结果状态更新为 `ENTERING_DFU`。
2. 等待当前 MSC 写事务和必要的 USB 状态传输完成。
3. 在 BKP 备份寄存器写入一次性 DFU magic。
4. 主动断开应用 USB 设备。
5. 执行 `NVIC_SystemReset()`。

Bootloader 必须读取并立即清除 BKP DFU magic。软件复位后 BKP magic 有效；后续复位不得因旧 magic 再次进入 DFU。

### 5.2 上电按键入口

Bootloader 必须在访问应用镜像前初始化最小按键 GPIO。按键稳定按下约 50 ms 时，Bootloader 进入恢复 DFU。

按键恢复模式不依赖以下内容：

- 应用镜像是否有效。
- Boot 状态是否完整。
- 设备配置是否有效。

正常 DFU 模式只接受高于当前已确认版本的固件。按键恢复模式允许同版本和降级，但仍必须检查芯片型号、目标槽、加载地址、长度、向量表和 CRC32。

### 5.3 停留规则

- DFU 等待下载时不设置空闲超时。
- 下载失败后不自动复位。设备保持 DFU 枚举，并允许主机通过 DFU 标准恢复请求重新开始下载。
- 下载成功并提交候选镜像后，设备自动复位。

## 6. USB 枚举和 DFU 状态机

应用模式保持现有 MSC、CDC-ACM 和 CMSIS-DAP v2 复合设备，不新增 DFU Runtime 接口。

Bootloader 模式枚举为独立 DFU 设备。DFU 设备必须使用与应用设备不同的 PID，使主机工具可以明确识别重新枚举。PID 常量必须集中定义，不得散布在描述符和主机工具中。

Bootloader 实施标准 USB DFU 1.1 控制传输和状态迁移。产品实现可以复用 GD32 DFU 示例的 USB 底层结构，但必须重写或封装内存访问和错误传播。以下要求为强制要求：

- `DNLOAD` 块长度不得超过声明的传输大小。
- 数据块必须按协议规定的顺序到达；跳块和非法重复块必须进入可报告的 DFU 错误状态。
- Flash 擦除、编程和回读失败必须反映到 DFU `bStatus`，不得继续返回 `STATUS_OK`。
- 最终 Manifest 状态传输完成前不得复位。
- `UPLOAD` 默认禁用。Bootloader 不通过 DFU 返回现有固件内容。
- `ABORT` 和 `CLRSTATUS` 只能从 DFU 规范允许的状态恢复。
- USB 断开后，未完成的候选镜像不得成为可启动镜像。

## 7. 升级包和镜像格式

发布物 `daplink_wireless.dwup` 包含公共清单、Slot A 镜像和 Slot B 镜像。两个镜像必须来自同一源码提交和同一个 `firmware_version_code`，仅链接地址和由地址产生的二进制内容不同。

公共清单至少包含以下字段：

- 包格式版本。
- 产品标识。
- 目标 MCU 标识 GD32F303CC。
- `firmware_version_code`。
- 供用户显示的语义版本字符串。
- A、B 镜像条目位置和长度。
- 清单 CRC32。

每个设备端镜像头至少包含以下字段：

- 固定 magic。
- 镜像头格式版本。
- 目标 MCU 标识。
- 目标槽标识。
- 加载地址。
- 镜像长度。
- `firmware_version_code`。
- 语义版本字符串。
- 镜像 CRC32。
- 镜像头 CRC32。

设备端镜像头必须位于传输流开头。Bootloader 必须在擦除目标槽前完成头部检查。

主机工具执行以下流程：

1. 修改应用 MSC 配置盘中的 `CONFIG.TXT`，写入 `ENTER_DFU=1`。
2. 等待应用设备断开。
3. 等待 DFU PID 枚举。
4. 读取设备的当前活动槽、当前确认版本、MCU 标识和恢复模式。
5. 从 `.dwup` 选择非活动槽对应镜像。
6. 执行 DFU 下载并显示设备返回的具体错误。
7. 等待设备成功响应 Manifest，然后观察设备自动复位和应用 PID 重新枚举。

主机工具的选择结果不构成授权。Bootloader 必须独立拒绝活动槽、错误地址、错误版本和越界长度。

## 8. 版本规则

版本比较只使用 32 位无符号 `firmware_version_code`。语义版本字符串只用于显示。

- 正常 DFU 模式要求候选版本严格高于当前已确认版本。
- 正常 DFU 模式拒绝同版本和降级。
- 按键恢复模式允许任意 `firmware_version_code`。
- 恢复模式不得放宽芯片型号、地址、长度、向量表或 CRC32 检查。

发布流程必须保证同一 `.dwup` 中的 A、B 镜像具有相同的版本代码和源码标识。

## 9. Boot 状态和原子提交

Boot 状态区域由两个 2 KiB 页组成。状态记录使用代数计数、记录 CRC 和最后写入的提交标记。新记录必须先写入非活动状态页并回读验证，再成为有效状态。

状态至少表示以下信息：

- 已确认活动槽。
- 已确认版本。
- 候选槽和候选版本。
- 候选镜像长度和 CRC32。
- `PENDING_TEST` 状态。
- 候选镜像试运行次数。
- 记录代数和提交标记。

试运行次数使用只从 1 编程为 0 的独立 Flash 标记。Bootloader 不得为了每次试运行计数而擦除状态页。

下载完成后，Bootloader 执行以下提交顺序：

1. 从目标 Flash 全量计算 CRC32。
2. 检查 MSP、复位向量和镜像范围。
3. 写入新的候选状态记录，但不修改旧状态页。
4. 回读并验证新状态记录。
5. 最后写入新记录提交标记。
6. 完成 DFU Manifest 状态响应。
7. 显示成功状态并执行系统复位。

在步骤 5 之前复位时，旧状态仍有效。在步骤 5 之后复位时，候选镜像处于 `PENDING_TEST`。

## 10. 应用启动和确认

Bootloader 跳转应用前必须检查：

- 初始 MSP 位于 `0x20000000–0x2000BFFF`，并满足栈对齐要求。
- 复位向量最低位为 1。
- 复位向量地址位于所选镜像声明范围内。
- 镜像长度不超过所选槽。
- 镜像头、Boot 状态和目标槽一致。

跳转前，Bootloader 必须禁用和清除中断，并停止 SysTick。Bootloader 必须恢复应用需要重新初始化的外设状态，设置 MSP，并将 `SCB->VTOR` 设置为所选槽的向量表地址。

如果候选镜像处于 `PENDING_TEST`，Bootloader 必须在每次跳转前消耗一个试运行标记。应用必须在以下条件全部满足后调用 `boot_confirm()`：

- 板级和时钟初始化成功。
- 设备配置读取完成。
- USB 初始化成功。
- 无线和串口桥初始化得到明确结果。
- 看门狗已启动。
- 主循环至少完成一次迭代。

`boot_confirm()` 必须原子提交新的已确认活动槽和版本。确认前不得擦除旧槽。

如果候选镜像连续三次未确认，Bootloader 必须清除候选关系并恢复旧的已确认槽。看门狗负责使卡死的候选应用重新进入 Bootloader。

## 11. 损坏状态处理

- 当前槽无效且另一个已确认槽有效时，Bootloader 启动另一个槽。
- 两个槽都无效时，Bootloader 保持恢复 DFU。
- 一个 Boot 状态页损坏时，Bootloader 使用另一个有效页。
- 两个 Boot 状态页都损坏时，Bootloader 进入恢复 DFU。镜像头不能证明镜像已经通过试运行确认，因此 Bootloader 不得仅凭槽内镜像有效就自动启动。
- Bootloader 不得仅根据较高版本号猜测哪个未确认镜像应启动。

升级、试运行和回退不得擦除 `0x0803F000–0x0803FFFF` 的设备配置。

## 12. `STAT_LED` 状态

Bootloader 和应用使用逻辑 LED 状态。板级层负责低电平有效极性。实施前必须核对 `board_pins.h`、文档和实板颜色，解决当前绿、蓝引脚标注不一致的问题。

| 状态 | 指示方式 |
|---|---|
| DFU 等待下载 | 蓝灯慢闪，约 1 Hz |
| 擦除或写入 | 蓝灯快闪 |
| 最终校验 | 蓝灯和绿灯同时快闪，即青色 |
| 下载并提交成功 | 绿灯常亮约 500 ms，然后自动复位 |
| 包头、版本或目标型号错误 | 红灯慢闪 |
| Flash 写入或最终 CRC32 失败 | 红灯快闪 |
| 新固件试运行 | 绿灯快闪；确认后恢复应用正常指示逻辑 |
| 三次试运行失败并准备回退 | 红灯和蓝灯交替闪烁数次，然后启动旧槽 |
| 两个应用槽都无效 | 红灯常亮，同时保持 DFU 可用 |

下载成功后的自动复位必须发生在最后一次 DFU 状态传输完成后。LED 延时不得使主机超时或把成功升级报告为失败。

## 13. 构建和发布产物

构建系统生成以下产物：

- `daplink_bootloader.elf` 和 `daplink_bootloader.bin`。
- `daplink_slot_a.elf` 和 `daplink_slot_a.bin`。
- `daplink_slot_b.elf` 和 `daplink_slot_b.bin`。
- `daplink_wireless.dwup`。
- `daplink_factory.hex`。

`daplink_factory.hex` 用于首次生产或从现有固件迁移。工厂镜像包含 Bootloader、一个已确认的应用槽和初始化 Boot 状态。工厂烧录流程必须保留设备配置区域，除非操作者明确选择整片初始化。

现有设备没有 Bootloader，因此首次迁移必须使用 SWD 或等效调试接口。USB DFU 只能用于 Bootloader 已部署的设备。

发布门禁必须检查：

- Bootloader 不超过 16 KiB。
- 每个应用镜像不超过 116 KiB。
- A、B 镜像来自同一源码提交。
- A、B 镜像版本代码相同。
- A、B 镜像加载地址与槽定义一致。
- `.dwup` 清单和所有镜像 CRC32 正确。

## 14. 软件验证

### 14.1 包和边界

测试以下输入并要求设备拒绝：

- 截断的头部或镜像。
- 未知格式版本。
- 错误 MCU 标识。
- 错误槽或加载地址。
- 超过槽大小的长度。
- 地址加长度整数回绕。
- 错误头部 CRC32。
- 错误镜像 CRC32。
- 正常模式中的同版本或降级镜像。

### 14.2 DFU 状态机

测试合法下载，以及乱序块、跳块、非法重复块、超长块、`ABORT`、`CLRSTATUS`、USB 中断和重新开始。每个 Flash 错误必须映射到可观察的 DFU 错误状态。

### 14.3 复位和掉电注入

在以下边界前后模拟复位：

- 页擦除。
- 每个数据块编程。
- Flash 回读。
- 最终 CRC32 计算。
- 新状态记录写入。
- 提交标记写入。
- 试运行标记写入。
- `boot_confirm()` 提交。

每次模拟后必须证明设备启动旧的已确认镜像、试运行完整候选镜像或保持恢复 DFU。设备不得跳转到部分写入的镜像。

### 14.4 A/B 和 MSC 入口

测试以下场景：

- A 升级到 B。
- B 升级到 A。
- 新固件成功确认。
- 新固件连续三次未确认并回退。
- 候选固件由看门狗复位。
- 单个和两个 Boot 状态页损坏。
- 精确的 `ENTER_DFU=1`。
- `ENTER_DFU=0`、错误值、重复字段和近似字段。
- MSC 分块写入、重复扇区写入和缓存刷新。
- 同一次写入修改普通配置并请求 DFU。

### 14.5 回归

必须运行现有 USB 复合描述符、MSC、CDC、CMSIS-DAP、无线协议、配置存储、Debug 构建、Release 构建和发布验证。软件测试通过不代表实板 USB 和掉电验收通过。

## 15. 实板验收

实板至少完成以下验收：

1. Windows 写入配置盘后，应用设备断开并以 DFU PID 枚举。
2. 按键上电可以在应用完全损坏时进入恢复 DFU。
3. `STAT_LED` 的实际红、绿、蓝颜色与状态表一致。
4. 主机收到成功 Manifest 状态后，设备自动复位并运行新槽。
5. 下载期间拔除 USB 后，重新上电仍可运行旧固件。
6. 错误 CRC32 镜像不能成为候选镜像。
7. 故障候选镜像连续三次未确认后自动回退。
8. 升级和回退后设备配置保持不变。
9. Windows 和 Linux 至少各完成一次完整升级。
10. 使用数据线、USB-C CC、电源、D+、D-、外部上拉和 48 MHz USB 时钟的实测结果确认枚举链路。

## 16. 不在本次范围内

- 固件数字签名、加密和安全启动。
- 通过 CDC 或 CMSIS-DAP Vendor 命令进入 DFU。
- 在应用复合设备中增加 DFU Runtime 接口。
- DFU 空闲超时和自动返回旧应用。
- 通过 DFU `UPLOAD` 读取现有固件。
- 无线固件升级。
