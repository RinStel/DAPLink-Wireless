# SWD 无线事务模型实验

## 目的

验证关闭 `SWD_COMMAND`、`SWD_BLOCK`、`SWD_BURST` 请求 ACK 后，是否可通过直接等待端到端响应减少一轮无线往返。

## 实施

- 新增 `SERIAL_BRIDGE_SWD_REQUEST_ACK_ENABLE` 编译开关。
- 默认值为 `1`，保留原有可靠事务行为。
- 实验版本 `1.0.42` 将其设为 `0`，主从两板同步升级。

## 结果

实验版本执行 64 KiB pyOCD 烧录时无正常输出，随后 CMSIS-DAP 探针掉线，诊断接口不可用。说明当前收发状态机仍依赖 SWD 请求 ACK；单纯删除 ACK 会破坏链路同步，不能作为吞吐优化。

已构建并通过 DFU 恢复版本 `1.0.43`（开关恢复为 `1`），单次 64 KiB 烧录恢复成功，速度 6.05 kB/s。

## 结论

后续若要减少 ACK，必须同时设计响应帧确认、半双工 TX/RX 状态同步和超时重传窗口，不能只删除请求 ACK。当前安全版本保持请求 ACK。
